# AttendanceAdmin UI 重新设计需求文档

**文档版本**: v1.0
**创建日期**: 2026-06-18
**状态**: 待审批

---

## 1. 概述

### 1.1 项目背景

AttendanceAdmin 是一个基于 Qt 6 QML 的 Windows 桌面考勤管理系统客户端。当前版本（v0.1）存在多个用户体验问题，需要进行全面的 UI 重新设计。

### 1.2 设计目标

- **提升操作效率**：减少重复操作，增加批量处理能力
- **改善易用性**：增加表单验证、优化登录体验、统一交互模式
- **增强视觉体验**：支持暗色模式、统一通知系统、优化布局响应式
- **支持通用规模**：适配小型到大型企业的不同数据量需求

### 1.3 目标用户

**主要用户**：企业 HR/行政人员
- 需要快速完成日常考勤管理操作
- 关注操作效率和界面易用性
- 需要直观的数据展示和报表导出

### 1.4 设计范围

本次为全面 UI 重构，覆盖所有 7 个功能模块和全局组件。

**模块重组说明**：

| 新模块 | 原模块 | 说明 |
|--------|--------|------|
| 仪表盘 | PageDashboard | 保持不变，功能增强 |
| 人员管理 | PagePerson | 保持不变，功能增强 |
| 设备管理 | PageDevice | 保持不变，功能增强 |
| 考勤管理 | PageAttendance | 保持不变，功能增强 |
| 人脸管理 | PageFace | 保持不变，功能增强 |
| 配置管理 | PageConfigDeploy | 保持不变，功能增强 |
| 系统管理 | PageUser + PageRbac + PageLogViewer | 合并为统一入口 |

## 2. 全局需求

### 2.1 窗口响应式（P0）

**需求描述**：
主窗口支持完全自由调整大小，最小尺寸 1024×700，无最大尺寸限制。

**用户故事**：
- 作为 HR，我希望调整窗口大小以适应不同显示器，以便在笔记本和大屏显示器上都能舒适使用
- 作为 HR，我希望将窗口缩小以便同时查看其他应用程序（如 Excel）

**验收标准**：
- [ ] 窗口可自由拖拽调整大小
- [ ] 最小尺寸限制为 1024×700
- [ ] 窗口尺寸变化时，布局自动适应（侧边栏固定，内容区伸缩）
- [ ] 记住上次关闭时的窗口尺寸和位置

**优先级**：P0

---

### 2.2 暗色模式（P1）

**需求描述**：
支持手动切换明暗主题，记住用户选择。Theme.qml 已定义暗色色板，需要实现切换机制。

**用户故事**：
- 作为 HR，我希望切换到暗色模式以减少长时间使用的眼睛疲劳
- 作为 HR，我希望系统记住我的主题选择，下次启动时自动应用

**验收标准**：
- [ ] 在状态栏或设置中提供主题切换入口
- [ ] 切换主题时所有界面元素同步更新
- [ ] 记住用户选择，下次启动自动应用
- [ ] 暗色模式下所有文字可读性良好

**优先级**：P1

---

### 2.3 统一通知系统（P0）

**需求描述**：
实现统一的 Toast 通知组件，支持成功/失败/警告/信息四种类型，自动消失。

**用户故事**：
- 作为 HR，我希望操作后看到统一的通知反馈，以便快速了解操作结果
- 作为 HR，我希望通知样式一致，不会因为不同页面而有不同的通知体验

**验收标准**：
- [ ] 实现全局单例 NotificationManager
- [ ] 支持 4 种通知类型：success、error、warning、info
- [ ] 通知自动消失（默认 3 秒），可手动关闭
- [ ] 通知位置统一（页面顶部居中）
- [ ] 所有页面使用统一的通知接口

**优先级**：P0

---

### 2.4 DataTable 组件增强（P0）

**需求描述**：
DataTable 组件增加排序、筛选、分页、导出功能，支持大数据量场景。

**用户故事**：
- 作为 HR，我希望点击表头对数据进行排序，以便快速找到需要的信息
- 作为 HR，我希望在表格中直接筛选数据，而不必每次都调用查询接口
- 作为 HR，我希望分页显示大数据量，避免一次加载过多数据导致卡顿
- 作为 HR，我希望将表格数据导出为 Excel，以便制作报表

**验收标准**：
- [ ] 支持点击表头排序（升序/降序/取消）
- [ ] 支持列级筛选（文本搜索、下拉选择）
- [ ] 支持分页显示（可配置每页条数：20/50/100）
- [ ] 支持导出为 CSV/Excel 格式
- [ ] 保持现有功能：列宽调整、行选中、右键菜单、斑马纹
- [ ] 大数据量（>1000 条）时性能良好

**优先级**：P0

---

### 2.5 表单验证框架（P0）

**需求描述**：
实现统一的表单验证框架，支持实时验证和提交前验证。

**用户故事**：
- 作为 HR，我希望输入时即时看到验证错误，以便及时修正
- 作为 HR，我希望提交表单前看到所有错误汇总，避免多次提交失败

**验收标准**：
- [ ] 实现 FormValidator 组件，支持配置验证规则
- [ ] 支持必填、长度、格式等验证规则
- [ ] 实时验证：输入时即时显示错误提示
- [ ] 提交前验证：汇总所有错误，弹窗提示
- [ ] 错误提示样式统一（红色文字 + 输入框红色边框）
- [ ] 所有表单页面使用统一验证框架

**优先级**：P0

## 4. 非功能需求

### 4.1 性能需求

| 场景 | 性能要求 |
|------|----------|
| 页面加载 | < 500ms |
| 表格渲染（1000 条） | < 1s |
| 表格排序/筛选 | < 300ms |
| 表单验证 | 实时响应 |
| 主题切换 | < 200ms |

### 4.2 兼容性需求

- **操作系统**：Windows 10/11
- **显示器**：支持 1024×768 及以上分辨率
- **Qt 版本**：Qt 6.8+

### 4.3 数据安全

- 登录凭据加密存储
- 敏感信息（如密码）不明文显示
- 操作日志完整记录

### 4.4 可维护性

- 组件职责单一，便于独立测试
- 使用 QML 单例管理全局状态
- 遵循现有设计系统（Theme.qml）
