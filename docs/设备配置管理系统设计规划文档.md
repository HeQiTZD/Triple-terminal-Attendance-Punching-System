# 设备配置管理系统设计规划文档

## 一、系统概述

### 1.1 设计目标

实现一套完整的设备端配置远程管理机制，支持管理端对设备配置进行集中修改、下发和生效，同时保障配置的安全性和一致性。

### 1.2 核心流程

```
管理端修改配置 → 管理端指定目标设备 → 管理端发送配置到服务端
→ 服务端保存配置到数据库 → 服务端转发配置到指定设备
→ 设备端接收完整配置文件 → 设备端校验配置有效性
→ 校验通过后覆盖旧配置 → 重新加载配置并生效
```

## 二、配置文件分治架构

### 2.1 设计原则

设备端采用 **双配置文件** 架构，将配置分为"可远程覆盖"和"本机私有"两类：

| 文件 | 内容 | 管理方式 | 文件位置 |
|------|------|----------|----------|
| `config.ini` | 人脸识别参数、考勤规则、设备信息 | 可被管理端远程下发覆盖 | `<应用程序目录>/config/config.ini` |
| `local.ini` | 网络地址、同步设置、存储路径、窗口尺寸 | 仅本机修改，不受远程影响 | `<应用程序目录>/config/local.ini` |

## 三、完整流程设计

### 3.1 管理端操作流程

#### 3.1.1 配置编辑

管理端提供可视化配置编辑界面，支持对以下三类配置进行修改：

- **人脸识别配置**：阈值、最大人脸数、识别超时、SDK密钥
- **考勤规则配置**：上下班时间、迟到容差、弹性工作制、午休时间等
- **设备信息配置**：设备名称、固件版本

#### 3.1.2 目标设备选择

管理端支持以下设备选择方式：

- **单设备**：通过设备ID精确指定
- **批量选择**：通过复选框选择多个设备
- **分组选择**：按设备分组（如按部门、楼层）批量选择
- **全选**：选择所有在线设备

#### 3.1.3 发送配置到服务端

管理端构造配置下发请求消息：

```json
{
  "type": "config.deploy",
  "from": "admin_console",
  "msgId": "<uuid>",
  "ts": 1716201600000,
  "data": {
    "targetDevices": ["device_001", "device_002", "device_003"],
    "configContent": "[FaceRecognition]\nFaceThreshold=85\n...",
    "configVersion": "2026.05.20.001",
    "description": "调整人脸识别阈值和上班时间"
  }
}
```

### 3.2 服务端处理流程

#### 3.2.1 数据库表设计

服务端需要建立配置文件存储表：

```sql
-- 设备配置部署记录表
CREATE TABLE device_config_deploy (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    config_version  VARCHAR(64) NOT NULL COMMENT '配置版本号',
    config_content  TEXT NOT NULL COMMENT '完整配置文件内容 (INI格式)',
    config_hash     VARCHAR(64) NOT NULL COMMENT '配置内容SHA-256哈希',
    description     VARCHAR(500) COMMENT '配置变更说明',
    created_by      VARCHAR(64) NOT NULL COMMENT '创建者 (管理端用户ID)',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_version (config_version),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='设备配置部署记录';

-- 设备配置下发目标表
CREATE TABLE device_config_target (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    deploy_id       BIGINT NOT NULL COMMENT '关联部署记录ID',
    device_id       VARCHAR(64) NOT NULL COMMENT '目标设备ID',
    status          ENUM('pending', 'sent', 'acknowledged', 'applied', 'failed') DEFAULT 'pending',
    error_message   VARCHAR(500) COMMENT '失败原因',
    sent_at         DATETIME COMMENT '发送时间',
    ack_at          DATETIME COMMENT '设备确认时间',
    applied_at      DATETIME COMMENT '配置生效时间',
    FOREIGN KEY (deploy_id) REFERENCES device_config_deploy(id),
    INDEX idx_deploy_device (deploy_id, device_id),
    INDEX idx_device_status (device_id, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='配置下发目标设备';

-- 设备当前配置版本表
CREATE TABLE device_config_current (
    device_id       VARCHAR(64) PRIMARY KEY COMMENT '设备ID',
    config_version  VARCHAR(64) NOT NULL COMMENT '当前配置版本',
    config_hash     VARCHAR(64) NOT NULL COMMENT '当前配置哈希',
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='设备当前配置版本';
```

#### 3.2.2 处理流程

```
1. 接收管理端配置下发请求
2. 验证配置内容格式有效性
3. 计算配置内容SHA-256哈希
4. 生成配置版本号
5. 保存配置到 device_config_deploy 表
6. 为目标设备创建 device_config_target 记录 (status=pending)
7. 对每个目标设备：
   a. 检查设备是否在线
   b. 在线：构造 device.command 消息发送配置，status=sent
   c. 不在线：保持 status=pending，等待设备上线后推送
8. 返回管理端操作结果
```

#### 3.2.3 下发到设备的消息格式

服务端构造 `device.command` 消息发送到设备：

```json
{
  "type": "device.command",
  "to": "device_001",
  "from": "server",
  "msgId": "<uuid>",
  "ts": 1716201600000,
  "data": {
    "command": "update_config",
    "params": {
      "config": "[FaceRecognition]\nFaceThreshold=85\n...",
      "configVersion": "2026.05.20.001",
      "configHash": "sha256:abc123..."
    }
  }
}
```

### 3.3 设备端处理流程

#### 3.3.1 接收与校验

设备端 `CommandHandler` 接收到 `update_config` 指令后的处理流程：

```
1. 提取 params.config (完整INI内容)
2. 提取 params.configVersion (配置版本)
3. 提取 params.configHash (配置哈希)

4. 校验步骤：
   a. 内容非空校验
   b. 哈希校验：计算收到内容的SHA-256，与configHash比对
   c. INI格式校验：用QSettings加载临时文件，检查status()
   d. 必要Section校验：检查是否包含[FaceRecognition]、[Attendance]、[Device]
   e. 关键字段校验：检查必填字段是否有值

5. 任一校验失败：
   - 发送 ack (success=false, code=校验失败码)
   - 记录错误日志
   - 终止流程

6. 全部校验通过：
   - 进入配置覆盖流程
```

#### 3.3.2 配置覆盖（原子替换）

```cpp
bool ConfigManager::applyRemoteConfig(const QString &configContent,
                                       const QString &configVersion,
                                       const QString &configHash)
{
    QString configPath = getConfigFilePath();

    // 1. 写入临时文件
    QString tempPath = configPath + ".tmp";
    // ... 写入 configContent 到 tempPath

    // 2. 格式验证
    QSettings tempSettings(tempPath, QSettings::IniFormat);
    if (tempSettings.status() != QSettings::NoError) return false;

    // 3. 备份原文件
    QString backupPath = configPath + ".bak";
    QFile::copy(configPath, backupPath);

    // 4. 原子替换
    QFile::remove(configPath);
    QFile::rename(tempPath, configPath);

    // 5. 重新加载
    delete m_settings;
    m_settings = new QSettings(configPath, QSettings::IniFormat, this);
    loadConfig();

    // 6. 保存版本信息
    m_configVersion = configVersion;
    m_configHash = configHash;

    return true;
}
```

#### 3.3.3 应答与状态上报

设备端处理完成后，发送 `device.command.ack` 消息：

**成功应答：**
```json
{
  "type": "device.command.ack",
  "inReplyTo": "<原始msgId>",
  "from": "device_001",
  "ack": true,
  "data": {
    "command": "update_config",
    "success": true,
    "result": "config applied",
    "configVersion": "2026.05.20.001"
  }
}
```

**失败应答：**
```json
{
  "type": "device.command.ack",
  "inReplyTo": "<原始msgId>",
  "from": "device_001",
  "ack": true,
  "code": 4001,
  "msg": "config validation failed",
  "data": {
    "command": "update_config",
    "success": false,
    "result": "missing [FaceRecognition] section"
  }
}
```

### 3.4 服务端状态更新

服务端收到设备应答后：

```
1. 根据 inReplyTo 找到对应的 device_config_target 记录
2. 更新 status:
   - success=true  → status='applied', applied_at=NOW()
   - success=false → status='failed', error_message=result
3. 更新 device_config_current 表的设备当前配置版本
```

## 五、错误处理与安全机制

### 5.1 配置校验规则

| 校验项 | 说明 | 失败处理 |
|--------|------|----------|
| 内容非空 | config 字段不能为空 | 返回错误码 4001 |
| 哈希校验 | SHA-256 比对 | 返回错误码 4002 |
| INI格式 | QSettings 解析成功 | 返回错误码 4003 |
| Section完整性 | 必须包含三个Section | 返回错误码 4004 |
| 字段类型 | 时间格式、数值范围 | 返回错误码 4005 |

### 5.2 安全机制

- **哈希校验**：防止传输过程中配置内容被篡改
- **备份回滚**：每次覆盖前备份原文件，失败时自动恢复
- **临时文件**：先写临时文件再重命名，避免写入中断导致配置损坏
- **日志记录**：记录每次配置变更的详细日志

### 5.3 错误码定义

```cpp
// 配置相关错误码 (4xxx)
constexpr int kCodeConfigHashMismatch   = 4002;  // 哈希不匹配
constexpr int kCodeConfigFormatInvalid  = 4003;  // INI格式无效
constexpr int kCodeConfigSectionMissing = 4004;  // 缺少必要Section
constexpr int kCodeConfigFieldInvalid   = 4005;  // 字段值无效
constexpr int kCodeConfigApplyFailed    = 4006;  // 配置应用失败
```

## 七、测试验证方案

1. 管理端修改配置 → 服务端保存 → 设备端接收覆盖 → 配置生效

2. 选择目标设备 device_001

5. 验证设备端 config.ini 已更新
6. 验证设备端内存中阈值已变为 85
7. 验证管理端显示配置下发成功
