# 设备端认证改进方案

## 文档信息

- **创建日期**: 2026-05-22
- **最后更新**: 2026-05-22
- **涉及项目**: 设备端 (`d:\QTproject\AttendanceSystem`)、服务端 (`d:\attendanceServer`)

---

## 1. 问题分析

### 1.1 现有问题

1. **认证流程复杂**
   - 新设备需要"待审核"流程
   - 状态流转逻辑复杂
   - 管理端和设备端需要多次交互

2. **已认证设备重连问题**
   - 已认证设备重新连接时可能误判为"待审核"
   - 状态判断逻辑不够清晰

3. **运维不便**
   - 设备上线需要等待审核
   - 批量部署设备时效率低

### 1.2 现有流程

```
设备连接 → 检查状态 → 待审核/验证密钥 → 管理端批准 → 认证成功
```

**问题**：流程冗长，需要管理端实时在线审核。

---

## 2. 简化方案

### 2.1 核心思路

**管理端预创建设备，设备端直接认证**

1. 管理端**提前**在数据库中创建设备记录（设置设备ID和密钥）
2. 设备端配置相同的设备ID和密钥
3. 设备连接时直接验证密钥，匹配即认证成功

### 2.2 方案优势

| 优势 | 说明 |
|------|------|
| **流程简单** | 无需待审核，设备连接即认证 |
| **运维友好** | 可批量预创建设备，提前配置 |
| **可靠性高** | 无中间状态，逻辑清晰 |
| **安全性好** | 密钥预分配，避免传输风险 |

### 2.3 简化后的流程

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        简化后的认证流程                                  │
└─────────────────────────────────────────────────────────────────────────┘

【部署阶段 - 管理端操作】
管理端 → 新建设备 → 设置设备ID + 密钥 → 保存到数据库

【运行阶段 - 设备端连接】
设备端 → 读取本地配置(deviceId, deviceKey) → 连接服务端
      → 发送认证请求 → 服务端验证密钥 → 认证成功/失败
```

## 3. 详细设计

### 3.1 设备状态定义

| 状态值 | 含义 | 说明 |
|--------|------|------|
| `offline` | 离线 | 设备已创建，当前未连接 |
| `online` | 在线 | 设备已连接并认证成功 |

**说明**：移除 `pending_auth` 状态，简化状态管理。

### 3.2 认证流程

#### 3.2.1 管理端创建设备

```
管理端操作界面
    ↓
输入设备信息：
  - 设备ID (deviceId)
  - 设备名称 (deviceName)
  - 设备密钥 (deviceKey)
    ↓
调用 API: POST /api/devices
    ↓
服务端保存到数据库：
  - device_id
  - device_name
  - key_hash (密钥哈希)
  - status = 'offline'
```

#### 3.2.2 设备端配置

设备端配置文件 (`config.json`)：
```json
{
  "deviceId": "device_001",
  "deviceKey": "your-secret-key",
  "serverIp": "192.168.1.100",
  "serverPort": 8080
}
```

#### 3.2.3 设备认证流程

```
设备启动
    ↓
读取本地配置 (deviceId, deviceKey)
    ↓
连接服务端
    ↓
发送认证请求: { type: "auth", deviceId: "xxx", deviceKey: "xxx" }
    ↓
服务端验证：
  1. 查询数据库中的设备记录
  2. 验证密钥是否匹配
    ↓
验证结果：
  - 成功 → 返回认证成功，状态设为 online
  - 失败 → 返回认证失败，拒绝连接
```

### 3.3 认证判断逻辑

**服务端核心逻辑**：

```cpp
void handleDeviceAuth(net::ISession& session, const ParsedEnvelope& env) {
    const std::string device_id = opt_data_string(env.data, "deviceId");
    const std::string device_key = opt_data_string(env.data, "deviceKey");
    
    // 1. 检查参数
    if (device_id.empty() || device_key.empty()) {
        session.write_line(build_error(kCodeAuthFailed, "missing deviceId or deviceKey"));
        return;
    }
    
    // 2. 查询数据库中的设备记录
    auto device_info = queryDevice(device_id);
    
    // 3. 设备不存在 → 拒绝连接
    if (!device_info.exists) {
        INFO_AUTH("设备不存在: deviceId=" << device_id);
        session.write_line(build_error(kCodeAuthFailed, "device not registered"));
        return;
    }
    
    // 4. 验证密钥
    if (!verifyDeviceKey(device_id, device_key)) {
        WARN_AUTH("设备密钥错误: deviceId=" << device_id);
        session.write_line(build_error(kCodeAuthFailed, "invalid device key"));
        return;
    }
    
    // 5. 认证成功
    // ... 生成JWT令牌、更新状态为online等
}
```

```
┌─────────────────────────────────────────────────────────────────────────┐
```

## 4. 实现方案

### 4.1 服务端修改

#### 4.1.1 简化 handleDeviceAuth 函数

**文件**: `d:\attendanceServer\protocol\GatewaySessionHandler.cpp`

**修改内容**：

```cpp
void GatewaySessionHandler::handleDeviceAuth(net::ISession& session, const ParsedEnvelope& env) {
    const std::string device_id = opt_data_string(env.data, "deviceId");
    const std::string device_key = opt_data_string(env.data, "deviceKey");
    const std::string ip_address = remote_ip_string(session);
    
    // 参数校验
    if (device_id.empty() || device_key.empty()) {
        INFO_AUTH("设备认证失败: 缺少参数 deviceId=" << device_id);
        session.write_line(build_error(kCodeAuthFailed, "missing deviceId or deviceKey", env.msg_id, {}));
        return;
    }
    
    // 查询设备信息
    bool device_exists = false;
    std::string device_key_hash;
    try {
        auto promise = std::make_shared<std::promise<bool>>();
        auto key_hash_ptr = std::make_shared<std::string>();
        
        db_.dispatch(
            [promise, key_hash_ptr, device_id](mysqlx::Session& s) {
                auto row = s.sql("SELECT key_hash FROM Device WHERE device_id = ?")
                             .bind(device_id)
                             .execute()
                             .fetchOne();
                if (row) {
                    *key_hash_ptr = row[0].isNull() ? "" : row[0].get<std::string>();
                    promise->set_value(true);
                } else {
                    promise->set_value(false);
                }
            },
            [promise](std::exception_ptr ep) {
                if (ep) {
                    try { promise->set_exception(ep); } catch (...) {}
                }
            });
        
        device_exists = promise->get_future().get();
        device_key_hash = *key_hash_ptr;
    } catch (const std::exception& ex) {
        std::cerr << "query device failed: " << ex.what() << '\n';
        session.write_line(build_error(kCodeDbError, "database error", env.msg_id, {}));
        return;
    }
    
    // 设备不存在 → 拒绝连接
    if (!device_exists) {
        INFO_AUTH("设备未注册: deviceId=" << device_id);
        session.write_line(build_error(kCodeAuthFailed, "device not registered", env.msg_id, {}));
        return;
    }
    
    // 使用 TokenManager 验证密钥
    auto result = tokenManager_->authenticateDevice(device_id, device_key);
    
    if (!result.success) {
        WARN_AUTH("设备密钥错误: deviceId=" << device_id);
        session.write_line(build_error(kCodeAuthFailed, result.errorMessage, env.msg_id, {}));
        return;
    }
    
    // 检查重复连接
    if (cfg_.duplicate_policy == service::DuplicateDevicePolicy::RejectNew &&
        registry_.has_live_session(device_id)) {
        session.write_line(build_error(kCodeDuplicateSession, "device already connected", env.msg_id, device_id));
        return;
    }
    
    // 注册设备会话
    auto reg = registry_.register_or_replace(device_id, session.shared_from_this(), cfg_.duplicate_policy);
    if (reg.status == service::DeviceRegisterStatus::RejectedDuplicate) {
        session.write_line(build_error(kCodeDuplicateSession, "device already connected", env.msg_id, device_id));
        return;
    }
    
    // 构建认证成功响应
    std::string reply;
    {
        std::lock_guard<std::mutex> lk(mu_);
        ConnContext& ctx = connections_[&session];
        ctx.endpoint_role = EndpointRole::Device;
        ctx.authenticated = true;
        ctx.device_id = device_id;
        ctx.bound_from = device_id;
        ctx.heartbeat_sec = cfg_.heartbeat_sec;
        ctx.accessToken = result.tokens.accessToken;
        ctx.refreshToken = result.tokens.refreshToken;
        ctx.tokenExpiresAt = util::JwtUtil::currentTimestamp() + result.tokens.expiresIn;
        
        arm_heartbeat(session, ctx);
        
        nlohmann::json data;
        data["accessToken"] = result.tokens.accessToken;
        data["refreshToken"] = result.tokens.refreshToken;
        data["tokenType"] = "Bearer";
        data["expiresIn"] = result.tokens.expiresIn;
        data["heartbeatSec"] = cfg_.heartbeat_sec;
        data["serverTime"] = util::JwtUtil::currentTimestamp() * 1000;
        
        reply = build_auth_response(env.msg_id, device_id, "device-session-" + device_id,
                                     cfg_.heartbeat_sec, data);
    }
    
    session.write_line(std::move(reply));
    INFO_AUTH("设备认证成功: deviceId=" << device_id << " ip=" << ip_address);
    
    // 更新数据库状态为 online
    db_.dispatch(
        [device_id, ip_address](mysqlx::Session& s) {
            db::DeviceRepository::upsertDeviceOnline(s, device_id, ip_address);
        },
        [](std::exception_ptr ep) {});
    
    // 推送设备上线事件
    nlohmann::json push_msg = {
        {"type", std::string(kTypeDeviceStatusPush)},
        {"role", std::string(kRoleServer)},
        {"from", std::string(kRoleServer)},
        {"ts", std::chrono::duration_cast<std::chrono::milliseconds>(
                   std::chrono::system_clock::now().time_since_epoch()).count()},
        {"code", 0},
        {"msg", "ok"},
        {"data", {{"deviceId", device_id}, {"status", "online"}, {"ipAddress", ip_address}}}
    };
    subscriptions_.publish("device", push_msg.dump());
}
```

```cpp
// 处理 device.create 命令
if (canon == std::string("device.create")) {
    if (ctx.endpoint_role != EndpointRole::Admin || !has_permission(ctx, "device.create")) {
        session.write_line(build_error(kCodeForbidden, "forbidden", env.msg_id, route_to));
        return;
    }
    
    const std::string device_id = opt_data_string(env.data, "deviceId");
    const std::string device_name = opt_data_string(env.data, "deviceName");
    const std::string device_key = opt_data_string(env.data, "deviceKey");
    
    if (device_id.empty() || device_key.empty()) {
        session.write_line(build_error(kCodeBusinessValidation, "missing deviceId or deviceKey", env.msg_id, route_to));
        return;
    }
    
    db_.dispatch(
        [device_id, device_name, device_key](mysqlx::Session& s) {
            s.sql("INSERT INTO Device (device_id, device_name, key_hash, status) VALUES (?, ?, ?, 'offline')")
              .bind(device_id, device_name.empty() ? device_id : device_name, device_key)
              .execute();
        },
        [this, &session, env, route_to](std::exception_ptr ep) {
            if (ep) {
                try { std::rethrow_exception(ep); }
                catch (const std::exception& ex) {
                    session.write_line(build_error(kCodeDbError, ex.what(), env.msg_id, route_to));
                }
                return;
            }
            session.write_line(build_report_ack("device.create.response", env.msg_id, route_to, 0, "ok", nullptr));
        });
    return;
}
```

## 5. 数据库设计

### 5.1 Device 表结构

```sql
CREATE TABLE Device (
    id INT PRIMARY KEY AUTO_INCREMENT,
    device_id VARCHAR(64) NOT NULL UNIQUE,
    device_name VARCHAR(128),
    key_hash VARCHAR(256) NOT NULL,  -- 设备密钥
    ip_address VARCHAR(45),
    last_online TIMESTAMP NULL,
    status ENUM('offline', 'online') DEFAULT 'offline',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

### 5.2 关键字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `device_id` | VARCHAR(64) | 设备唯一标识，由管理端分配 |
| `key_hash` | VARCHAR(256) | 设备密钥，用于认证 |
| `status` | ENUM | 只保留 `offline` 和 `online` |

## 6. 测试验证

### 6.1 测试场景

| 场景 | 预期结果 |

| 管理端创建设备 | 设备记录保存成功，状态为 offline |

- [ ] 设备断开后状态变为 offline

## 7. 总结

### 7.1 方案对比

| 项目 | 原方案 | 简化方案 |
|------|--------|----------|
| 设备状态 | 3种 (pending_auth, offline, online) | 2种 (offline, online) |
| 认证流程 | 连接→待审核→批准→认证 | 连接→认证 |
| 管理端操作 | 实时审核 | 提前创建设备 |
| 运维复杂度 | 高 | 低 |

### 7.2 核心改进

1. **移除待审核流程** - 管理端提前创建设备，设备直接认证
2. **简化状态管理** - 只保留 offline/online 两种状态
3. **提高可靠性** - 无中间状态，逻辑清晰
4. **便于运维** - 支持批量预创建设备

### 7.3 实施步骤

1. 修改服务端 `handleDeviceAuth` 函数
2. 新增管理端设备创建接口
3. 移除待审核相关代码
4. 更新设备端配置文件格式
5. 测试验证
