# 项目深度学习和理解文档 — AttendanceAdmin

## 一、项目概述

这是一个 **Qt6/QML 考勤管理客户端**，基于 TCP 协议与考勤服务器（attendanceServer）通信，提供人员管理、设备管理、考勤记录查询、人脸识别、RBAC 权限管理等功能。前端采用 QML 构建，后端逻辑通过 C++ 服务类实现，使用 Qt 的信号槽机制进行组件间通信。

**核心业务流程**：管理员通过 QML 界面操作 → C++ Service 类封装请求 → TcpConnectionManager 发送 JSON 消息到服务器 → 接收响应 → 更新 UI。

**与 attendanceServer 的关系**：本项目是 attendanceServer 的管理端客户端，通过 TCP 连接与服务器通信，发送管理指令并接收响应。

## 三、模块详解

### 1. `src/Models/` — 数据模型层

#### 文件职责

| 文件 | 职责 |
|---|---|
| `Person.h/cpp` | 人员信息模型（id, name, employeeId, department, position, createdAt, updatedAt） |
| `attendancerecord.h/cpp` | 考勤记录模型（id, employeeId, personName, checkTime, deviceId, status, receivedTime） |
| `device.h/cpp` | 设备信息模型（id, deviceId, deviceName, ipAddress, lastOnline, status, deviceKey） |
| `faceData.h/cpp` | 人脸数据模型（id, employeeId, personName, featureVector, createdAt, updatedAt, featureSize） |

#### 设计思路

**QObject 模型 + Q_PROPERTY**：所有模型类都继承自 `QObject`，使用 `Q_PROPERTY` 宏声明属性，支持：
- QML 数据绑定（自动同步 UI）
- 信号通知（属性变化时自动触发 `*Changed` 信号）
- JSON 序列化/反序列化（`toJson()` / `fromJson()`）

```cpp
// src/Models/Person.h:8
class Person : public QObject {
    Q_OBJECT
    Q_PROPERTY(int id READ id WRITE setId NOTIFY idChanged)
    Q_PROPERTY(QString name READ name WRITE setName NOTIFY nameChanged)
    Q_PROPERTY(QString employeeId READ employeeId WRITE setEmployeeId NOTIFY employeeIdChanged)
    // ... 更多属性
public:
    QJsonObject toJson() const;
    static Person* fromJson(const QJsonObject &json, QObject *parent = nullptr);
};
```

**设计亮点**：
- 属性变化时先检查是否真的变化（`if (m_xxx != xxx)`），避免不必要的信号发射
- `fromJson()` 是静态工厂方法，返回 `QObject*` 以便 QML 使用
- 所有属性都有独立的 getter/setter/信号，符合 Qt 最佳实践

#### 数据流

```
QML 界面绑定 Person 属性
       │
       ▼
  Person::setName("张三")
       │
       ├── m_name = "张三"
       └── emit nameChanged()
               │
               ▼
          QML 自动更新绑定的 UI 元素
```

### 3. `src/Network/` — 网络层

#### 文件职责

| 文件 | 职责 |
|---|---|
| `TcpConnectionManager.h/cpp` | TCP 连接管理、消息收发、自动重连、心跳、令牌管理 |

#### 设计思路

**核心架构：Qt 事件驱动 + 回调机制**

```cpp
// src/Network/TcpConnectionManager.h:12
class TcpConnectionManager : public QObject {
    Q_OBJECT

    // 连接状态枚举
    enum class ConnectionState {
        Disconnected,
        Connecting,
        Connected,
        Authenticated
    };

    // 连接配置
    struct ConnectionConfig {
        QString host = QStringLiteral("127.0.0.1");
        quint16 port = 9527;
        QString clientId = QStringLiteral("admin_001");
        int heartbeatSec = 30;
        int reconnectMaxAttempts = 10;
        int requestTimeoutMs = 10000;
    };

    // 响应回调类型
    using ResponseCallback = std::function<void(const QJsonObject &response)>;
};
```

**消息发送流程**：
```cpp
// 发送消息并注册响应回调
QString sendMessage(const QJsonObject &message, ResponseCallback callback = nullptr);
```

1. 生成唯一 `msgId`
2. 将消息序列化为 JSON 行
3. 通过 `QTcpSocket` 发送
4. 如果有回调，存储到 `m_pendingRequests` 映射表
5. 启动超时定时器（默认 10 秒）

**消息接收流程**：
```cpp
void processJsonLine(const QByteArray &line);      // 解析 JSON 行
void processReceivedMessage(const QJsonObject &message); // 处理消息
```

1. 从 socket 读取数据到 `m_readBuffer`
2. 按 `\n` 分割 JSON 行
3. 解析 JSON 对象
4. 检查是否有对应的 `PendingRequest`（通过 `msgId`）
5. 如果有，调用回调并移除定时器
6. 否则，发射 `messageReceived` 信号

**自动重连机制**：
```cpp
void scheduleReconnect();      // 调度重连
int nextReconnectDelayMs() const; // 计算退避延迟
```

- 使用指数退避算法：`delay = baseDelay * 2^attempts`（最大 30 秒）
- 最大重试次数：10 次（可配置）
- 连接成功后重置重试计数器

**心跳机制**：
```cpp
void startHeartbeat();   // 启动心跳定时器
void onHeartbeatTimeout(); // 心跳超时处理
```

- 每 30 秒（可配置）发送心跳消息
- 服务器回复心跳响应
- 超时未收到响应则断开连接

**JWT 令牌管理**：
```cpp
void refreshTokens();  // 刷新令牌
void addTokenToMessage(QJsonObject &message); // 添加令牌到消息
```

- 自动在消息中添加 `accessToken`
- 令牌过期前自动刷新
- 刷新失败时发射 `tokenRefreshFailed` 信号

**待处理请求管理**：
```cpp
struct PendingRequest {
    ResponseCallback callback;
    QTimer *timer;
};

QMap<QString, PendingRequest> m_pendingRequests;
```

- 使用 `QMap` 存储待处理请求
- 键是 `msgId`，值是回调和定时器
- 请求完成或超时时自动清理

#### 数据流

```
QML 调用: tcpManager.sendMessage({type: "person.query", data: {...}}, callback)
       │
       ▼
  TcpConnectionManager::sendMessage()
       │
       ├── 生成 msgId
       ├── 序列化为 JSON 行
       ├── 添加 accessToken
       ├── socket->write(jsonLine + "\n")
       │
       └── 存储到 m_pendingRequests[msgId] = {callback, timer}
               │
               ▼
          启动 10 秒超时定时器
               │
               ▼
  [服务器处理并返回响应]
               │
               ▼
  TcpConnectionManager::onSocketReadyRead()
       │
       ├── 读取数据到 m_readBuffer
       ├── 按 "\n" 分割 JSON 行
       │
       ▼
  processJsonLine(line)
       │
       ├── JSON 解析
       ├── 提取 msgId
       │
       ├── [有对应 PendingRequest]
       │       │
       │       ├── 调用 callback(response)
       │       ├── 移除定时器
       │       └── 从 m_pendingRequests 移除
       │
       └── [无对应 PendingRequest]
               │
               └── emit messageReceived(message)
```

| 文件 | 职责 |
|---|---|

#### 设计思路

**SessionManager 是 TcpConnectionManager 的高层封装**：

```cpp
// src/Auth/SessionManager.h:11
class SessionManager : public QObject {
    Q_OBJECT

    Q_PROPERTY(bool isLoggedIn READ isLoggedIn NOTIFY loggedInChanged)
    Q_PROPERTY(QString sessionToken READ sessionToken NOTIFY sessionTokenChanged)
    Q_PROPERTY(QString accessToken READ accessToken NOTIFY accessTokenChanged)

```

**登录流程**：
```cpp
void login(const QString &host, int port,
           const QString &username, const QString &password,
           const QString &clientId = QString());
```

1. 递增 `m_authEpoch`（防止旧请求干扰新会话）
2. 如果已连接，先断开
3. 清除旧会话数据
4. 构建 `ConnectionConfig`
5. 调用 `m_tcp->connectToServer(config)`

**认证事件处理**：
```cpp
void onTcpAuthenticated(const QString &token,
                        const QStringList &roleList,
                        const QStringList &permList);
```

- 接收服务器返回的 `sessionToken`、`roles`、`permissions`
- 更新本地状态
- 发射 `loggedIn` 信号

**权限检查**：
```cpp
Q_INVOKABLE bool hasPermission(const QString &permKey) const;
Q_INVOKABLE bool hasRole(const QString &roleKey) const;
```

- 在 QML 中直接调用，用于 UI 权限控制

**设计亮点**：
- `m_authEpoch` 机制：每次登录递增，防止旧的异步回调干扰新会话
- `SessionManager` 作为 `TcpConnectionManager` 的子对象，保证析构顺序
- 所有状态都通过 Q_PROPERTY 暴露，QML 可直接绑定

#### 数据流

```
QML 登录按钮点击
       │
       ▼
  SessionManager::login("192.168.1.100", 9527, "admin", "password")
       │
       ├── ++m_authEpoch
       ├── m_tcp->disconnectFromServer()  // 如果已连接
       ├── clearSession()
       │
       ▼
  TcpConnectionManager::connectToServer(config)
       │
       ├── socket->connectToHost()
       │
       ▼
  [TCP 连接建立]
       │
       ▼
  TcpConnectionManager::sendAuth()
       │
       ├── 发送: {"type":"auth", "data":{"username":"admin", "password":"..."}}
       │
       ▼
  [服务器验证并返回响应]
       │
       ▼
  TcpConnectionManager::processReceivedMessage()
       │
       ├── type == "auth_response"
       │
       ├── 提取: sessionToken, roles, permissions, accessToken, refreshToken
       │
       ├── 存储到本地状态
       │
       └── emit authenticated(token, roles, permissions)
               │
               ▼
  SessionManager::onTcpAuthenticated()
       │
       ├── m_isLoggedIn = true
       ├── m_sessionToken = token
       ├── m_roles = roleList
       ├── m_permissions = permList
       │
       └── emit loggedIn(token, roles, permissions)
               │
               ▼
          QML 跳转到主界面
```

**标准的 Server 类模式**：

```cpp

class PersonServer : public QObject {
    Q_OBJECT
    Q_PROPERTY(bool busy READ busy NOTIFY busyChanged)
    Q_PROPERTY(QVariantList records READ records NOTIFY recordsChanged)

public:
    Q_INVOKABLE void createPerson(const QString& name,

                                  const QString& department,

                                  const QString& name,
                                  const QString& department,
                                  const QString& position);

    Q_INVOKABLE void deletePerson(const QString& employeeId);

```

**请求-响应模式**：
```cpp
void PersonServer::createPerson(const QString& name, ...) {
    // 1. 参数验证
    if (!m_tcp || !m_tcp->isAuthenticated()) {
        emit operationFailed(kPersonCreate, -1, "未连接或未认证");
        return;
    }

    // 2. 构建请求
    QJsonObject data;
    data[kName] = name;
    data[kEmployeeId] = employeeId;
    // ...
    QJsonObject msg;
    msg[kType] = kPersonCreate;
    msg[kData] = data;

    // 3. 设置忙碌状态
    setBusy(true);

    // 4. 发送请求并注册回调
    m_tcp->sendMessage(msg, [this](const QJsonObject& resp) {
        setBusy(false);

        // 5. 处理响应
        if (resp.isEmpty()) {
            emit operationFailed(kPersonCreate, -1, "请求超时");
            return;
        }

        const int code = resp.value(kCode).toInt(-1);
        if (code != ErrorCode::kSuccess) {
            emit operationFailed(kPersonCreate, code, resp.value(kMsg).toString());
            return;
        }

        // 6. 更新本地数据
        // ...

        // 7. 发射成功信号
        emit operationSucceeded(kPersonCreate, "创建成功");
    });
}
```

**设计亮点**：
- `Q_INVOKABLE` 宏使方法可从 QML 直接调用
- `busy` 属性用于显示加载状态
- `records` 属性存储查询结果，QML 可直接绑定到 ListView
- 统一的错误处理模式：超时、业务错误、成功

```cpp
Q_INVOKABLE void registerFace(const QString &employeeId,
                              const QString &photoBase64,
                              bool overwrite = false);

Q_INVOKABLE void registerFaceFromFile(const QString &employeeId,
                                      const QString &filePathOrUrl,
                                      bool overwrite = false);
```

**二进制帧传输**：
1. 发送 `face.register.header` 消息，声明照片长度
2. 调用 `m_tcp->sendBinaryFrame(payload)` 发送二进制数据
3. 等待服务器响应

**本地文件处理**：
```cpp
static QString normalizeLocalPath(const QString &filePathOrUrl);
static QString readFileAsBase64(const QString &localPath, QString* errorOut);
```

- 支持 QML FileDialog 的 `file://` URL 格式
- 读取本地文件并转换为 Base64

**查询结果缓存**：
```cpp
Q_PROPERTY(QVariantList records READ records NOTIFY recordsChanged)
Q_PROPERTY(bool lastFound READ lastFound NOTIFY lastFoundChanged)
Q_PROPERTY(QVariantMap lastRecord READ lastRecord NOTIFY lastRecordChanged);
```

- `records`：所有查询过的记录列表
- `lastFound` / `lastRecord`：最近一次查询结果

### 11. `src/Event/` — 事件服务

#### 文件职责

| 文件 | 职责 |
|---|---|
| `EventSubscriptionService.h/cpp` | 事件订阅管理、服务端推送消息处理 |

#### 设计思路

**事件订阅机制**：
```cpp
Q_INVOKABLE void subscribe(const QStringList &topics);
Q_INVOKABLE void unsubscribe(const QStringList &topics);
```

- 发送 `subscribe` / `unsubscribe` 消息到服务器
- 服务器将该连接加入/移除订阅列表
- 有新事件时，服务器推送给所有订阅者

**推送消息处理**：
```cpp
void onTcpMessageReceived(const QJsonObject &message);
```

- 检查消息类型是否是推送类型（如 `attendance.push`、`device.status.push`）
- 提取数据并发射 `serverPushReceived` 信号
- 其他服务（如 `DeviceServer`）连接此信号处理特定推送

**设计亮点**：
- 使用 `QSet` 去重订阅主题
- 限制最大订阅数量
- 自动在认证后重新订阅（断线重连时）

## 六、关键设计模式

| 模式 | 实现 | 作用 |
|---|---|---|
| **信号槽** | Qt signals/slots | 组件间松耦合通信，自动线程安全 |
| **Q_PROPERTY** | 所有 Model/Server 类 | QML 数据绑定，属性变化自动通知 |
| **Q_INVOKABLE** | 所有 Server 类的业务方法 | QML 可直接调用 C++ 方法 |
| **回调函数** | `ResponseCallback = std::function<void(const QJsonObject &)>` | 异步请求-响应模式 |
| **观察者模式** | `EventSubscriptionService` | 事件订阅与推送 |
| **状态机** | `ConnectionState` 枚举 | 连接状态管理 |
| **工厂方法** | `Person::fromJson()` | JSON 反序列化 |
| **单例** | QML 单例类型（Theme, Logger, History 等） | 全局共享状态 |
| **依赖注入** | 所有 Server 类通过 `setTcpManager()` 注入 | 解耦网络层 |
